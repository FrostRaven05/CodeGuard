# 本次提交的模型评审与系统密钥存储

2026-10-18。阶段二首批实现模型服务配置与本次提交评审。

首个接口采用可配置地址的 Chat Completions 兼容协议：主进程向指定服务的 `/chat/completions` 发送 `model`、`messages`、`stream: false`，读取文本响应并验证评审 JSON。不要求供应商支持专有结构化输出参数，不宣称兼容所有供应商。连接测试只发送测试文字。已用本机 HTTP 服务验证协议、错误与取消；真实供应商的连通性和评审质量由用户配置后验证。

Windows 桌面通过 Electron `safeStorage` 加密密钥，普通 JSON 仅包含加密密文和非敏感设置。IPC 只返回密钥是否存在，不回显密钥。加密不可用时不保存明文；浏览器临时预览明确采用仅进程内保留密钥的模式。模型配置损坏不影响 Git 使用，重存前备份原文件。

仓库服务固定 HEAD、暂存树和分支，再从不可变 Git 对象读取差异。发送预览展示文件与排除项；发送前检查快照、模型和依据是否改变。默认排除常见敏感路径、生成目录、疑似密钥内容、非普通文件、二进制和超预算内容；敏感文件重命名后继续排除。本批只提供暂存差异和用户填写的规范、需求，不自动扩展到整个项目或执行项目脚本。

评审服务管理准备、运行、取消、错误和最近结果。网络请求不占据 Git 写队列，评审状态不参与提交许可判断。请求完成后仍可识别内容、HEAD、分支、模型或依据变化，过期结果显示旧版本。失败和取消保留旧结果与提交草稿，取消不承诺撤销服务端费用。

模型响应按不可信数据处理：验证格式、文件、版本侧、差异中的行号及连续代码摘录，丢弃不能核对的候选并显示数量。此检查只确认位置和摘录，不能证明缺陷成立；所有发现均标记“AI 推断待确认”。缺少需求明确显示未核对，检查固定显示未运行。界面以文本渲染结果，模型没有执行 Git、运行命令或修改源码的入口。

暂存树使用 `write-tree` 固定，与原有提交预览共享快照语义；可能生成 Git 树对象，不切换工作区、不改动用户文件和暂存内容。记录保存在应用用户目录，不写入被添加的仓库。

参考：[Chat Completions 请求与响应协议](https://developers.openai.com/api/reference/resources/chat)、[Electron safeStorage 的平台保护语义](https://www.electronjs.org/docs/latest/api/safe-storage)。
