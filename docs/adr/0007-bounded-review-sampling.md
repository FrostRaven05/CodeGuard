# 分离安全读取、差异预算与附近上下文预算

2026-11-13。修订 ADR-0003 和 ADR-0006 的读取及预算分配。

原实现把源文件字节大小与发送差异预算绑定，大文件即使只改一行也被跳过。附近上下文按前十二个改动行生成，窗口互相重叠但分别收费，新版本和靠前文件还会先耗尽预算。相关扫描只有四十个候选，Markdown 被作为不支持关联语言逐条提示。以上限制既损失证据，又产生大量重复提示。

现在普通文件安全读取上限为 1 MB，依然先检查整个读取对象的敏感内容、二进制和 Git 文件类型；这一上限与发送字符预算分开。代码评审为附近上下文保留约四分之一可用空间，先保留较小差异，剩余空间由较大差异共享。超过份额的差异按完整行拆成带真实旧/新版本坐标的片段，分散选取首尾及中部；单行也放不下时不发送。结果记录 partialFiles，模型和界面都明确部分覆盖，不把采样称为整文件已评审。提交信息生成保持完整差异语义，不沿用评审采样。

附近上下文先合并重叠范围，再按文件、版本和片段共同分配字符预算；必要时围绕改动锚点收窄。TS/JS、Python 保留有限函数与引用识别，其余文本含 Markdown 提供普通附近文本，不冒充语义关系。只为分散的改动区域设十二个候选限制，相关同目录/测试候选扩至八十个。所有路径、重命名排除、链接隔离和敏感内容规则继续适用。

全局搜索所预留预算显式随准备快照保存；搜索函数对非有限预算按零处理，避免未保存参数导致 NaN 比较失效。最终请求仍按公共最大字符数再次检查，结果及引用仍只允许从实际发送的证据中核对。

限制记录在服务侧按文件和原因去重，界面兼容旧记录并将预算类提示合并、默认折叠。差异未纳入、差异部分覆盖与附近上下文受限分别表达。图解只放行为前后及简短结论，流程单独使用纵向图、不自动缩小文字；核对过程和代码证据按需展开。建议区移除人工处置及备注表单，旧处置数据和存储接口继续保留兼容性。
