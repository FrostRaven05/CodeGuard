# 显式预览的同步与分支操作

2026-10-18。用户要求在顶部工具栏和分支菜单补齐获取、拉取、推送、切换与合并，保持界面简洁。

GitOperations 使用现有 GitService 的仓库目录和串行写队列，通过固定业务接口提供选项、准备和执行；渲染端不提供命令、URL 或任意 refspec。预览保存目标提交、当前分支/HEAD、索引与工作区版本、操作状态以及远端配置摘要。执行前重核，实际 Git 仍负责跨进程锁与覆盖检查；不承诺消除外部程序与钩子的竞态，执行后刷新真实状态。

获取显式选择已有远端；拉取的预览先获取所选远端分支，再固定其提交，仅允许 ff-only，不继承 pull.rebase 或隐式合并。分叉可从同一面板请求显式合并固定来源。普通推送使用固定提交到明确 refs/heads 目标，不提供强制、镜像或标签推送；多推送地址拒绝执行，避免一次确认写往多个位置。无上游必须选择目标，建立上游为显式选项。

切换只选现有本地分支，保留 Git 对无覆盖风险改动的正常携带行为。合并要求干净工作区，显式禁用 autostash、子模块递归及分支 mergeOptions，保留钩子和签名配置。冲突不自动回滚，外部解决并暂存后预览继续提交，也可预览中止。AI 评审从不作为执行条件。网络操作使用现有 Git 认证，不在应用内保存远端密码；错误中的 URL 凭据经过过滤。

参考：[Git push](https://git-scm.com/docs/git-push)、[Git merge](https://git-scm.com/docs/git-merge)、[Git switch](https://git-scm.com/docs/git-switch)。
