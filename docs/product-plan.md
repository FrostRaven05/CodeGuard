更新日期：2026-11-09。状态：Git 工作台、模型配置、本地改动理解、本次提交流式评审、远端同步和分支切换/合并已实现。草稿自动保存、问题处置/复查、差异连续浏览和历史分页搜索已通过回归、生产构建与真实桌面验收。当前改动文件常驻左侧，分支入口集中于顶部菜单，已支持 Windows 安装版与免安装版。历史/分支评审与手动检查等尚未实现。启动见根目录 README.md，任务见 `.scratch/git-workbench/`、`.scratch/ai-review/` 与 `.scratch/git-sync/`。

## 1. 产品定位

CodeGuard 是面向个人开发者的 Windows 桌面 Git 工具。它帮助使用者看懂 AI 生成的改动、核对问题和证据，并完成日常提交、推送、拉取与本地分支合并。

界面风格和操作主要参考 GitKraken，改动选择参考 VS Code Git。AI 直接接入用户配置的模型服务。工具解释和评审代码；编码助手负责修复；使用者决定执行 Git 操作。

核心流程：选择改动 → 理解变化 → 查看问题与验证证据 → 必要时交给编码助手 → 选定提交内容 → 预览并执行操作。

### 已确认与方案建议

已确认：个人自用、Windows 桌面、默认全部本地改动、摘要优先、独立模型接入、可配置规范、需求可选、评审只提醒、手动检查、默认仅快进拉取、冲突外部处理，以及 TS/JS、Python、Rust、Go、C++ 的评审需求。

第一阶段已采用 Electron、React 和 TypeScript，记录于 ADR-0001。模型配置、分析器顺序和后续阶段中的实现细节仍按下文建议，在相应阶段验证。

## 3. 界面与信息层级

建议使用克制的深色工作台、彩色分支线、紧凑列表和可调整面板。颜色表达分支、增删和状态，文字及图标同时表达含义。保持原创界面，不使用 GitKraken 的商标、图标或素材。

```text
仓库 / 当前分支                         获取  拉取  推送  设置
────────────────────────────────────────────────────────────
改动文件   │ 当前改动 | 提交历史             │ 评审侧栏
           │                                │
未暂存     │ 点左侧文件：源码差异           │ 范围 / 依据
已暂存     │ 历史：彩色提交图与提交列表       │ 问题与证据
未跟踪     │                                │ 验证结果
           │ 点文件：源码差异                │ 验证结果
────────────────────────────────────────────────────────────
当前范围 / 数据状态 / 操作结果                   上下文主操作
```

默认打开上次仓库的“当前改动”。不先展示统计仪表盘。设置放侧抽屉，不在主界面堆放模型参数、规则选项或分析器开关。

工作台主要文字与按钮使用 14px，辅助信息至少 12px，窄窗口不缩小字体。右栏在常规窗口为 360px、窄窗口为 330px，集中显示提交说明、暂存范围、提交和分析操作；默认在 1080×700 首屏可见。移除重复导航、分支卡、仓库状态、装饰标题与常驻草稿说明。分析侧栏只保留一个自动选择范围的按钮、简短状态及结果入口：有暂存内容时评审本次提交，否则理解全部本地改动，不保留手动范围切换。问题、依据、覆盖与用量在可视化主区查看，规范与需求按需展开。分析点击即进入进度，提交按钮直接执行；范围、排除、过期及失败反馈仍保留，远端与分支操作继续使用确认面板。

Windows 桌面使用与工作台融合的深色顶栏，保留原生窗口按钮；中央空白区可拖动。仓库切换采用深色菜单，显示当前项及路径，支持键盘选择、Esc 和外部点击收起。

应用窗口、任务栏、Windows 安装/卸载与免安装程序统一使用深色底、薄荷绿 Git 分支的 CodeGuard 图标，不沿用 Electron 默认图标。图标源为 SVG，Windows ICO 包含 16–256 像素多个尺寸；网页图标沿用同一来源。

### 当前改动

左侧栏常驻按未暂存、已暂存、未跟踪分组的文件树，保留分组及目录折叠、整文件暂存与取消暂存；计数放在分组及提交侧栏。文件树独立滚动，管理远端与移除仓库位于底部。空分组隐藏，无改动时显示简短空状态。主区显示所选文件差异，未选择文件时提示从左侧选择，不重复展示改动列表。查看全部改动不会自动暂存文件。分支历史、切换与合并统一使用顶部菜单，移除左侧重复的本地与远端分支列表。

从任何主视图点击左侧改动文件会进入当前改动并打开对应未暂存或已暂存差异；选中版本高亮。当前改动差异可关闭，上一/下一文件保留，文件导航使用常驻左栏。历史提交使用右侧改动文件树，支持目录折叠、状态、重命名提示和选中高亮；所有差异主区移除重复左侧文件列表及其切换按钮，保留上一/下一文件和当前位置。差异工具栏可直接暂存此文件、取消暂存及暂存全部，操作后显示实际暂存版本，避免反复返回列表。暂存、取消暂存直接响应点击，不逐次弹确认框。右栏显示提交说明和已暂存文件数，“提交”按钮本身即为确认，不再打开二次预览；空说明、空暂存、锁或冲突时禁用，失败保留草稿。

改动文件标题右侧提供“暂存全部”，由用户点击后将整个仓库的新增、修改、删除与重命名加入暂存区，包含已暂存后再次编辑的最新内容；遵循 Git 忽略规则，不修改工作区或草稿。执行共用仓库写队列，运行中显示反馈并刷新实际结果；无待暂存内容、索引锁或未解决冲突时禁用。冲突须逐个核对后显式暂存，不能借此一键标为已解决。

### 操作反馈

预览展示在当前抽屉或面板，不串联多个确认弹窗。提交、推送、合并分别执行。成功、失败、冲突和状态已变化各有明确文字；失败时保留提交草稿和用户选择。

## 4. 评审范围与版本

界面始终显示范围名称、目标及版本状态，详细 Git 标识放在可展开区域。

| 范围 | 分析对象 | 注意事项 |
| --- | --- | --- |
| 全部本地改动 | HEAD 到当前工作区，并额外纳入经排除规则过滤的未跟踪文件 | 默认查看入口，不等于本次提交 |
| 本次提交 | HEAD 到索引中的内容 | 同一文件未暂存的新修改不能替代索引版本 |
| 单个历史提交 | 普通提交的父版本到该提交 | 根提交按空树比较；合并提交默认第一父视角并明确标注，可切换父视角 |
| 分支差异 | 源与目标的共同祖先到源分支 | 显示源分支引入的变化，不冒充合并后的最终结果 |

这些比较语义遵循 [Git diff 文档](https://git-scm.com/docs/git-diff)。无共同祖先、浅历史缺失或无法解析引用时显示具体原因，不悄悄更换比较范围。

一次评审固定快照，关联仓库、HEAD、索引、文件内容、需求文档、有效规范及模型配置版本。内容或评审依据变化后，旧结论显示“基于旧版本”；失败或被跳过的部分不能显示为已评审。

全部改动评审完成后，如果本次暂存区只包含其中一部分，显示两者差别；不能直接标记“本次提交已评审”。可复用有效证据，但提交范围的结论需要重新核对。提交说明始终从最终暂存区生成。

## 5. AI 评审流程

用户点击唯一分析按钮后，按最新暂存状态确定本次范围，在一个后台任务中完成以下步骤，界面可继续浏览差异：

1. 固定范围和版本，收集差异、相关实现、必要测试与选定依据。
2. 进度显示实际准备和请求阶段，结果显示分析覆盖与排除原因；超出配置预算的内容跳过或报错，由用户缩小范围，不自动扩大发送范围。
3. 生成行为变化摘要；按内容选择需要的检查视角。
4. 分别检查代码正确性、规范符合度和需求符合度。工具已有确定性结果时不重复制造风格建议。
5. 对候选问题再核验触发条件、代码证据、行号和是否由本次改动引入，合并重复问题。
6. 展示问题、覆盖情况、验证结果及未知项；保留可追溯版本。

首版可用多个有明确职责的模型步骤实现，不预设复杂自治代理团队。一个“评审”按钮即可，不向用户暴露一排技能或代理角色。

2026-11-02 引入本地理解与本次提交评审 SSE 流式请求，2026-11-09 改为点击即进入主区进度，无二次发送确认。准备阶段显示实际依据保存和快照准备，之后显示真实版本核对、请求等待、接收输出、结果校验和保存阶段，以及耗时、接收字符数、已生成摘要和完成位置核对的问题。完整字段经过敏感内容与排除路径检查后展示；生成内容与正式结果分开，不展示原始 JSON 或供应商内部推理，不编造逐文件检查或测试执行。桌面通过隔离 IPC 推送过程，临时浏览器预览读取轻量内存进度；过程按仓库和范围隔离、不落盘。准备期间取消不会发送模型请求；完成自动收起过程，取消、断流、超时和失败保留旧结果与提交草稿。服务返回整包 JSON 时继续兼容，不自动重试请求。

2026-11-11：修复长思考流因重复协议元数据提前触发响应大小限制的问题。传输总量、单事件和最终正文分别受限；收到 reasoning_content 时只显示“模型正在分析改动”，不展示或保存推理文本，正文开始后进入接收阶段。代码评审的请求上限为 5 分钟，连接测试与提交信息生成仍为 90 秒；保留主动取消。正文继续受配置预算限制，断流、异常与取消不会保存为完成结果。

AI 可以提出进一步评审的建议、生成提交草稿和准备结构化操作建议；Git 操作由使用者点击触发，模型不能自行执行。提交按钮即为本次提交确认，内部固定并重核暂存快照；远端同步与分支操作继续在面板内核对后确认。首版从桌面界面进入，外部编码助手通过 CLI 或 MCP 发起请求作为后续候选接口，不把该集成默认为已实现。

### 发现格式

每条问题记录：优先级、问题描述、触发条件、相关位置、证据、后果、修复方向、所属评审维度及依据来源。跨语言接口问题可关联多处代码。

证据状态分为“检查结果支持／静态分析支持／AI 推断待确认”，不把模型自报分数当成可靠概率。规范问题标为约定符合性；启发式设计建议与确定缺陷区分呈现。

输出“本范围未发现问题”，不输出“代码完全安全”。没有需求文档时显示“未核对需求”，检查未执行时显示“未运行”。

### 评审与 Git 的关系

评审只提醒，不强制拦截。未评审、结论过期、有待处理问题时，使用者仍可在看到提醒后提交或合并。正常路径不要求填写豁免理由。

仓库处于冲突、存在锁或操作会覆盖改动等实际 Git 条件仍需处理。这些属于执行条件，不是 AI 评审门禁。

## 6. 需求与可配置代码规范

需求文档按次可选，首版建议支持 Markdown、纯文本和用户直接输入的需求说明。复杂文档导入后续增加。需求与代码规范各自有来源、版本和评审状态。

规范设置提供三个层次：通用评审基线、自动发现的项目规范、用户明确配置的覆盖。优先级建议为“用户明确覆盖 > 项目约定 > 通用基线”；不同来源冲突时展示生效规则及来源。

用户可以在设置中编辑规范，也可主动将共享规则保存到仓库。建议使用 `.codeguard/review.md`，无需另学规则语言。例如用户可以要求“错误必须包含上下文”“公共接口变化需要兼容性说明”“不要重复报告格式化工具能处理的问题”。

自动发现候选包括 CONTRIBUTING、CODING_STANDARDS、用户指定文档及语言工具配置。读取文件中的约定不等于执行其中脚本；不把仓库文本当成授权外传数据、运行命令或改变工具行为的指令。

语言规则可分组配置：TS/JS 关注类型与异步行为，Python 关注异常与资源边界，Rust 关注错误传播与 unsafe，Go 关注错误处理与并发，C++ 关注生命周期与资源管理。这些是候选检查方向，不代表工具已经能够完整证明相关性质。

变更规范后保留历史评审所用版本，当前结论注明依据已更新。

## 7. 多语言支持与图示

首版覆盖 TypeScript、JavaScript、Python、Rust、Go、C++ 的差异、AI 文本评审、需求和规范核对、配置检查及修复交接。不承诺所有语言具有同等精度的符号解析或跨项目语义能力。

| 层次 | 首版建议 |
| --- | --- |
| 差异与代码证据 | 所列语言均支持，包含常见扩展名和路径 |
| AI 上下文 | 按改动与相关代码收集；按预算限制；显示覆盖情况 |
| 外部检查 | 通过用户配置的命令接入已有工具，不自动安装或修改项目 |
| 行为示意 | 按需生成小型流程图或前后对比，明确标为解释性示意 |
| 静态关系 | 首版先保留可追溯的文件依赖；符号与调用解析按技术实验结果逐步开放 |

检查配置示例：TS/JS 的测试、类型检查和 lint；Python 的测试与 lint；Rust 的测试和 clippy；Go 的测试与 vet；C++ 的项目构建、测试或静态检查。实际命令由用户选择，不假定工具已安装或命令适用于所有仓库。

show-me 的价值落实为“用最小图解释当前变化”。可优先采用前后对比、局部流程和引用位置。解析器确认、AI 推断和未知关系使用不同标识；模型生成的行为图不命名为真实调用图。全仓库调用图留待后续。

## 8. 检查命令与验证证据

每个仓库可以配置命令、参数和工作目录，主界面通过一个“运行检查”入口选择执行。首次保存配置时展示具体内容，执行由用户点击触发；不因打开仓库或启动评审自动运行项目脚本。

结果至少包括：命令、执行目录、开始/结束时间、退出状态、日志与实际代码对象。状态区分未运行、运行中、通过、失败、取消和结果已过期。

首版默认在当前工作区运行检查。因此：

- 未暂存改动存在时，检查对象可能不同于索引中的本次提交，必须显示差异。
- 查看历史提交或其他分支时，当前工作区检查不能算作被选中对象的验证。
- 检查期间代码变化，结果注明对象发生变化；格式化或测试产生改动时刷新文件状态。
- 在独立快照环境验证暂存区或历史版本作为后续增强，不自动切换或清理真实仓库。

AI 可以解释真实输出，不能编造测试通过、执行次数、性能提升或验证覆盖。

## 9. Git 操作流程

### 提交

提交说明标题旁显示带文字的“生成提交信息”按钮；点击后直接准备固定暂存快照并调用模型，不弹发送确认框。成功后填入可编辑草稿，原位显示准备、生成、取消及失败反馈；重复点击不重复调用，准备或生成期间人工编辑时保留用户内容。暂存内容版本按路径、模式和对象内容判断，Git 缓存刷新不触发草稿过期提示。

2026-11-11：准备阶段取消立即恢复生成按钮，保留草稿，可直接重试。已开始的本地快照计算可能继续完成，但取消任务不会再发起模型请求；迟到的成功或失败响应不能清除新任务的进度或覆盖草稿。仓库切换沿用按仓库重新挂载生成组件的隔离方式。

选文件暂存 → 展示本次提交 → 生成并编辑说明 → 显示评审与检查状态 → 点击提交 → 显示哈希与实际结果。

2026-11-09：“预览提交”改为“提交”，一次点击等待最新草稿保存，内部准备并核对固定暂存版本后执行，无确认弹窗。运行中显示正在提交并禁止重复操作；版本变化或钩子失败显示真实错误、保留草稿，不自动重试、暂存或推送。用户随后手动重试时会重新固定快照。

模型生成的提交说明采用 Conventional Commits：`type(scope): 中文摘要`，范围可省略，必要正文与标题之间空一行。生成规则限定常见类型 feat/fix/docs/style/refactor/perf/test/build/ci/chore/revert，范围为简短小写英文模块名，标题不超过 72 个 Unicode 字符；类型白名单、范围约束与长度为本产品的附加规则。提示词与响应校验共同约束格式，不合规结果不会替换草稿。不得包含未暂存内容或虚构测试、问题编号和兼容性承诺；破坏性标记仅用于差异有明确依据的变更。用户仍可手动编辑说明，Git 提交保留既有钩子与签名要求；索引变化后保留草稿并提示更新。格式参考 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/zh-hans/v1.0.0/)。

提交前重核索引和目标，提交后核验实际提交树。仓库钩子或外部工具可能在执行期间修改索引，所以不能承诺“执行前核对即可原子保证内容相同”。遵循真实钩子、签名和提交结果，不跳过钩子、不自动回滚。若实际提交与评审快照不同，展示事实并标记旧评审；后续动作需新的操作预览，仍不强制重新评审。[Git commit](https://git-scm.com/docs/git-commit)、[Git hooks](https://git-scm.com/docs/githooks)。

### 推送

显示本地分支 → 远端/分支及待推送提交，用户确认后执行普通推送。没有上游时先选择目标，不猜测远端。非快进拒绝、认证和网络错误分别提示；首版不提供强制推送。

### 远程仓库管理

侧栏直接提供“管理远程仓库”。从无远端的同步操作进入后，保存地址可点击“继续获取远端／拉取／推送”返回原操作，再预览执行，避免重新寻找入口。

仓库下拉菜单提供管理窗口；无远端的同步窗口可直接进入添加。查看远端名称、获取地址、独立推送地址与关联上游分支，支持添加、编辑地址、恢复默认推送地址及确认删除。保存按钮确认本次配置变更；删除前在原窗口说明将移除本地连接、远端跟踪分支和关联上游，保留本地分支与服务器仓库。

管理操作共用仓库写队列，使用 Git 参数接口，只改当前仓库本地配置，不请求网络。外部配置变化后拒绝旧表单；Git 失败保留输入并提示核对，多个配置写入部分完成时如实说明，不自动回滚。全局/引入配置只读，已有多地址完整展示并保留，暂通过系统 Git 编辑；界面不将复杂配置静默压成单地址。密码和令牌遮蔽，输入地址不接收内嵌密码或令牌，认证仍沿用系统 Git。

### 拉取

获取远端状态 → 能快进则更新 → 本地与远端分叉时展示比较及“显式合并”入口。使用明确的仅快进策略，不依赖用户全局 Git 默认设置；fetch 更新远端跟踪状态，不等于工作区已更新。[Git pull](https://git-scm.com/docs/git-pull)。

### 切换分支

展示目标分支，检查本地改动状态。若存在覆盖风险则保留当前状态并说明原因，不自动 stash、不强制切换。分支选择与历史浏览是两个动作。

### 合并与冲突

选择源分支 → 展示源 → 当前目标、提交范围、文件及已有评审 → 用户确认合并 → 显示真实结果。

存在目标分支独有改动时，提醒源分支评审不等于已验证最终集成结果；合并预检仅作参考，不能承诺无冲突或无语义问题。

遇到冲突后列出冲突文件，保留 Git 当前进行中状态；支持打开外部编辑器和复制处理说明。编码助手处理后，刷新并由用户确认暂存与完成合并。提供用户显式发起的“中止本次合并”，预览适用状态和 Git 的实际限制；不中断外部正在进行的操作，不自动清理残留文件。

所有 Git 写操作按仓库排队；外部编辑器和 Git 客户端仍可能同时修改仓库，因此执行前后都需刷新。锁、冲突、rebase 等状态按真实原因显示，不删除锁文件冒充修复。

## 10. 模型、数据与配置

设置页优先通过下拉选择服务和模型，当前提供 DeepSeek 官方服务及模型预设；选择自定义服务才填写地址和模型 ID，预设服务也可选择自定义模型。已保存的非预设配置原样识别，切换时保留本次草稿。密钥与连接测试单独提供，选择和保存本身不调用模型。首版采用 Chat Completions 兼容接口；“可自行配置服务”不等于任意供应商都无需适配。

调用由用户触发，理解、评审和提交信息生成均点击即执行，不弹发送确认框；只发送对应范围内已过滤的固定差异与受控上下文，结果提供覆盖与未纳入原因。排除配置涵盖密钥文件、生成物、二进制、超大文件及用户指定路径；排除项也适用于摘要、日志和修复交接，不能从其他上下文路径绕过。外部引用、符号链接与子模块不自动扩大到未授权目录。

密钥使用系统保护的本地存储，不进入仓库配置、普通日志或界面导出。模型响应与仓库文本作为不可信内容处理，不允许其直接发起 Git 写操作或任意命令。

用户级设置保存模型与个人默认项；仓库本地设置保存选择、排除和命令。共享规则需要用户主动保存到仓库，添加仓库本身不写入项目文件。

费用已知时展示真实用量；服务不返回价格或用量时显示未知。上下文预算可配置，大范围分析先提示缩小或分批。取消会停止后续请求，已产生调用不伪装为免费或已撤销。

无网络时仍可查看差异、暂存、编辑提交草稿和执行可用的本地 Git 操作。模型失败保留现有结果并标注失败部分。

## 11. 实现结构建议

第一阶段采用 Electron + React + TypeScript：界面主要使用统一的前端技术，本地服务借助主进程调用系统 Git。优点是实现工作台和进程交互方便，代价是安装体积和运行开销。取舍见 `docs/adr/0001-local-electron-workbench.md`；安装包体积仍需在后续打包阶段评估。

界面进程只表达用户意图；本地服务负责 Git、快照、模型请求、检查执行和系统保护的密钥存储。通过有参数校验的业务接口通信，不向页面暴露任意命令执行入口。Electron 实现应启用上下文隔离及渲染沙箱，关闭渲染端 Node 集成。上下文隔离与操作系统进程沙箱是不同机制。[进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)、[上下文隔离](https://www.electronjs.org/docs/latest/tutorial/context-isolation)、[沙箱](https://www.electronjs.org/docs/latest/tutorial/sandbox)。

Windows 可使用 Electron safeStorage 的系统加密能力保存密钥；它不承诺抵御同一登录用户下所有程序。[safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。

| 模块 | 责任 |
| --- | --- |
| 仓库服务 | 状态、差异、历史、分支、串行写操作、错误与刷新 |
| 快照服务 | 固定范围、索引/内容标识、过期检测、证据关联 |
| 评审服务 | 上下文选择、有效规则、模型步骤、候选复核与缓存 |
| 检查服务 | 用户配置、执行、取消、日志与对象匹配 |
| 设置服务 | 模型、密钥、规则、排除和仓库偏好 |
| 界面 | 概览、图与列表、差异、问题卡片、操作预览 |

Git 调用使用可执行文件和参数数组，明确仓库路径，不拼接不可信 shell 文本。检查命令属于用户显式配置的执行入口，单独处理其 shell 与参数规则，不与 Git 参数封装混为一谈。

核心数据为仓库、评审范围、快照、评审运行、发现、检查运行、提交草稿和操作记录。发现、检查证据和草稿均保留适用版本。首版采用本地持久化，暂不增加云同步、账号或服务端。

## 12. 交付阶段与验收

### 阶段一：Git 工作台骨架

交付仓库、改动、整文件暂存、差异、提交历史图、提交与分支状态。通过临时仓库覆盖暂存后再次编辑、空仓库、重命名、删除、未跟踪文件以及 Windows 特殊路径。

通过条件：界面范围与真实 Git 状态一致；不会把未暂存修改算进本次提交；提交失败不丢草稿。

### 阶段二：AI 评审与配置

2026-10-18 已实现：兼容 Chat Completions 的模型配置与连接测试、系统保护密钥、固定暂存快照与发送预览、可选文本规范和需求、摘要与问题证据、位置校验、取消、复制交接及过期状态。补充了固定暂存树/父版本的 TS/JS、Python 有限文本上下文，预览展示来源、行范围、大小及未纳入原因；上下文遵守共同预算和排除，不证明语义调用关系。评审不拦截提交。已使用本机模拟服务验证真实 HTTP 与桌面桥接，并以 DeepSeek 官方 API 完成四组合成样例；助手结合独立执行真值核对，两项回归检出、误报 0、漏报 0，仅限此组小样例，不是用户人工验收。实际用量 5514 tokens，费用未知，证据见 `.scratch/ai-review/evidence/2026-10-18-deepseek.md`。项目规范自动发现、其他评审范围与更多真实任务质量评估留待后续。验证流程见 `docs/model-validation.md`，上下文取舍见 ADR-0003。

交付自行配置模型、规范与需求选择、摘要、问题证据、三类评审对象、修复交接和过期状态。所列语言均进入差异与文本评审验收，分别用真实样例评估质量。

通过条件：每条问题可定位；无需求显示未核对；无检查显示未运行；超时、无效行号、部分覆盖和文件变化不会显示成完整通过。

### 阶段三：同步、合并与验证

2026-10-18 已实现同步与分支操作：顶栏获取、仅快进拉取、普通推送；分支菜单切换已有本地分支、合并本地或远端跟踪分支。统一面板预览方向、固定版本、提交和文件，执行前检查版本与配置。拉取分叉可显式转合并；冲突保留，支持外部解决并暂存后的继续提交和预览中止。无上游须选择远端目标；可明确建立上游。系统 Git 认证、钩子与签名沿用；不提供强制推送、自动 stash 或自动冲突解决。已用临时裸远端、克隆和隔离桌面验证，未对用户远端试写；见 `.scratch/git-sync/README.md` 与 ADR-0004。手动检查仍待后续。

交付手动检查、推送、仅快进拉取、分叉预览、显式合并及外部冲突处理后的继续/中止流程。

通过条件：检查对象标注准确；分叉不会悄悄变基；冲突可理解并保留工作；钩子和签名错误如实反馈；操作对象变化会更新预览，评审问题仍不构成强制门禁。

### 实际使用验收

由用户用真实任务比较原有流程与新工具：看懂一次改动需要多久、多少问题确有价值、是否还需频繁切换终端、完成提交与合并是否更清楚。记录误报、遗漏、成本和耗时，不用建议数量或综合质量分数衡量价值。

技术实验另外验证：大历史图的响应、超大 diff、模型结构化输出、跨语言上下文、Windows 检查取消、现有 Git 认证，以及钩子修改索引后的结果核验。验证写操作使用临时仓库。

## 13. 当前建议与下一步

第一阶段已交付两种主视图、文件级暂存、真实差异、提交预览、提交与历史图。第二阶段首批已在右栏接入本次提交的 AI 评审，模型配置收纳于独立面板。2026-11-09 提交说明旁的“生成提交信息”改为直接生成，不再弹窗；从固定暂存差异生成 Conventional Commits 可编辑草稿并校验格式。生成失败、取消、版本变化或准备/生成期间人工编辑均保留原草稿，生成不会执行提交。该能力已通过本机模拟模型和隔离桌面交互验证，真实服务的生成质量仍需实际使用评估。

后续接入其他评审范围、项目规范发现和手动检查，使用更多真实任务评估模型质量。同步、合并与冲突恢复已补齐，取舍见 ADR-0004；首批模型协议、密钥与评审快照取舍见 ADR-0002。

## 15. 2026-10-25 产品体验修正

- 规范与需求自动保存到应用本地存储，显示保存中、已保存和失败重试；切换视图/仓库保留草稿，准备发送等待最新保存完成。
- 默认分析范围为“全部本地改动”，可先理解 HEAD 到工作区与未跟踪文件，再选择提交内容。“本次提交”仍从索引固定版本分析；两类最近结果和问题处置隔离，提交预览只引用提交范围的评审。
- 全部本地改动通过应用目录中的独立索引固定到不可变 Git 树，不修改真实索引或工作文件；不执行项目过滤器、文本转换或钩子。忽略规则、敏感路径、链接/子模块、二进制、内容检测与预算共同限制范围；发送前以内容核对快照，后续变化标记旧版本。采用原始工作区字节，不声称与 Git clean filter 后的暂存对象等价。
- 问题记录待处理、已处理、忽略及处理备注；依据路径、版本侧、维度、标题与整行证据保守匹配，行号移动不清除处置，无法稳定匹配时保留为独立问题。复查区分再次发现、本轮未再发现可定位问题、未覆盖；均不自动判定已验证修复。
- 差异页提供可收起文件列表、上一/下一文件、版本标签和当前位置；返回概览或历史恢复滚动位置。评审定位始终读取所选结果的固定快照，避免 HEAD 到工作区与索引到工作区的差异混用。
- 左侧分支明确为浏览入口，顶部明确当前检出及切换/合并。历史支持分支范围、跨未加载历史的说明标题/作者/哈希搜索、继续加载和实际已加载数量。搜索结果省略非匹配提交，不冒充完整历史图。

验证：新增离线回归 12 项通过，生产构建通过。完整测试的 HTTP 模拟请求和 Git/MSYS 子进程受执行环境限制，桌面集成进程未能启动；浏览器拒绝本地文件协议预览，未绕过策略。交互与视觉仍需在正常桌面环境完成验收，详见 `.scratch/ux-review/`。快照及处置取舍见 ADR-0005。
