# CodeGuard

简洁的 Windows 本地 Git 工作台，界面参考 GitKraken。已支持仓库管理、真实差异、整文件暂存与取消、提交预览与提交、彩色分支历史、获取/拉取/推送、分支切换与合并，以及模型配置和本次提交的 AI 评审。

已支持无需暂存的“理解全部本地改动”和独立的“评审本次提交”，两类结果分别保存，规范与需求自动保存。建议区直接显示触发条件、影响和修复建议，可定位和复制交接；已移除人工处置及备注表单，旧记录保留。历史提交与分支差异评审、项目规范自动发现及手动检查仍待后续接入。

## 启动

需要 Node.js 22.12+ 和系统 Git。依赖已经安装时，双击 `Start-CodeGuard.cmd`，或在项目目录执行：

```powershell
npm start
```

首次获取项目后先执行 `npm install`，再启动。Electron 的桌面运行时在首次安装或启动时需要下载。

如果系统 npm 启动脚本配置异常，可直接运行 `node scripts/start.mjs`。开发模式为 `npm run dev`。

双击启动会隐藏后台控制台；启动日志位于 `.local/launch.log` 和 `.local/launch-error.log`。

## Windows 打包

在 Windows 上安装开发依赖后执行 `npm run package`，先检查类型并构建前端，再生成 Windows x64 产物：

- `release/CodeGuard-0.1.2-Setup-x64.exe`：安装版，可选择安装目录，创建桌面和开始菜单快捷方式。
- `release/CodeGuard-0.1.2-Portable-x64.exe`：免安装版，双击运行。

产物文件名随 `package.json` 中的版本号变化。`npm run package:dir` 仅生成 `release/win-unpacked/CodeGuard.exe` 及配套资源；该目录必须整体保留。首次打包需要联网下载打包工具和 Electron 运行时。

最终用户无需安装 Node.js，但仍需安装系统 Git 并将其加入 PATH。两种打包版都将配置、加密密钥和评审记录保存在 `%APPDATA%/CodeGuard/`，不会自动导入源码运行时 `.local/desktop/` 的配置；免安装版也使用此用户数据目录。卸载默认保留用户数据。打包采用运行资源白名单，不包含开发目录、本地配置或仓库数据。

窗口、任务栏和 Windows 安装/卸载及免安装程序使用 CodeGuard 自有图标。图标源为 `public/codeguard.svg`，修改后运行 `node scripts/generate-icons.mjs` 重新生成 `electron/assets/` 内的 PNG 与多尺寸 ICO，再构建打包。

当前构建未配置代码签名证书，Windows 可能显示未知发布者提示。

## 日常操作

1. 打开已有本地仓库，默认查看全部改动。
2. 左侧常驻当前改动文件树，按未暂存、已暂存、未跟踪分组，目录可逐层折叠并独立滚动。点击文件在中间查看该版本的真实差异；同一文件可分别出现在未暂存和已暂存组。历史提交使用右侧“改动文件”目录树切换文件；差异主区不再重复文件列表，保留上一/下一文件与当前位置，评审快照也沿用这些连续浏览操作。
3. 文件右侧 `＋` 暂存整文件，`−` 取消暂存；改动文件标题右侧“暂存全部”一次暂存仓库内全部新增、修改、删除和重命名，遵循忽略规则。无待暂存内容、索引锁或未解决冲突时按钮禁用。暂存遵循 Git 配置，可能运行仓库配置的 clean filter。
4. 填写提交说明，或点击旁边的“生成提交信息”直接生成可编辑草稿，不再弹窗。成功后替换草稿，准备/生成期间的人工编辑、失败和取消均保留原内容。生成只依据已暂存内容，复用“模型设置”的服务、排除与预算；部分文件未发送时会明确提示。格式采用 `type(scope): 中文摘要`（范围可省略），标题不超过 72 个字符，正文前空一行；不合规的模型结果不会写入。点击“提交”直接提交已暂存内容，无二次弹窗；空说明、空暂存、锁或冲突时禁用，运行时显示进度并防止重复提交。既有钩子和签名设置正常生效，失败保留草稿。
5. 顶部“当前检出”显示工作分支，菜单中的分支名称用于浏览历史，并提供切换与合并。历史显示已加载数量，可继续加载，并在当前分支范围内搜索全部历史的说明标题、作者或哈希；“全部历史”恢复所有分支。选中提交后点击文件查看差异，合并提交明确使用第一父视角。
6. 顶部“获取”更新所选远端的跟踪状态；“拉取”先获取并预览，仅快进更新。分叉时可在同一面板另行预览显式合并。
7. 顶部“推送”展示本地分支 → 远端/分支及提交后，确认普通推送。没有上游时必须选远端和分支，可明确勾选建立上游；只推送预览中的提交，不强制推送或发送标签。
8. 点击顶栏当前分支打开菜单，在目标分支旁选择“切换”或“合并…”。来源和目标、提交及文件在同一面板核对后执行。切换只支持已有本地分支，远端跟踪分支可合并；菜单中的分支名称仍用于浏览历史。
9. 顶部仓库下拉菜单 → “远程仓库管理”，添加远端名称和获取地址，按需设置独立推送地址；卡片右侧可编辑或删除。删除前会说明远端跟踪分支和关联上游的影响，服务器仓库与本地分支保留。无远端时，同步窗口也提供添加入口。
9. 合并冲突会保留并显示在改动列表；外部解决并暂存后，从分支菜单或冲突提示中选择“继续合并…”。也可预览“中止合并…”，由 Git 尝试恢复，失败时保留现场。

从仓库列表移除只解除关联。程序不自动暂存、推送、修改源码或删除锁文件。提交时内部固定并核对暂存版本；执行前暂存内容或分支变化会停止并报错，草稿保留，用户可核对后重新点击提交。提交后再次核对实际提交内容。远端与分支操作仍在预览面板中确认。

拉取和合并要求干净工作区；切换分支由 Git 判断改动能否安全保留，不自动 stash。远端认证沿用系统 Git 的凭据或 SSH 设置，认证和网络错误分开显示。地址管理只修改当前仓库的本地配置，不连接网络；全局/引入配置与已有多地址会显示并保留，其中多地址暂需通过系统 Git 编辑。多个推送地址会拒绝执行，避免一次确认推送到多个位置。同步与分支操作验证见 [.scratch/git-sync](.scratch/git-sync/README.md)。

仓库列表和提交草稿在开发运行时保存在 `.local/desktop/workspace.json`，不会写入所添加的仓库。该目录已排除版本控制。

## 本地改动理解与本次提交评审

1. 点击右上角“模型设置”，填写兼容 Chat Completions 接口的服务地址（通常含 `/v1`）、模型 ID 与密钥，点击“保存并测试”。也可填写完整 `/chat/completions` 地址。本机免密服务可留空密钥。
2. 右侧只保留一个分析按钮：有暂存内容时显示“评审本次提交”，只分析索引版本；没有暂存内容时显示“理解全部本地改动”，分析工作区与未跟踪文件。点击后核对最新 Git 状态再固定本次范围，运行期间不切换范围；无改动时禁用。“规范与需求”可选填写，自动保存并显示保存状态，失败可重试。
3. 点击后不弹发送确认，直接进入“改动图解”的实际进度：固定版本和附近上下文 → 模型提出简短假设 → 程序跨目录搜索固定快照 → 模型结合实际证据生成结论。准备时取消不会发送请求；请求中可停止等待，已产生调用仍可能计费。结果首先展示行为前后对比与影响流程，再连接假设、命中片段、结论和修复建议。可按文件筛选、点击流程节点查看依据、缩放流程图、定位对应差异行并返回；问题可复制给编码助手，修复由编码助手负责。

两种评审范围均请求 Chat Completions SSE 流式输出。过程只展示完整且经敏感内容检查的摘要字段与完成代码位置核对的问题；生成期间仍为 AI 推断，完成前不能按正式结果定位或处置。原始 JSON 和供应商内部推理不展示。服务若返回整包 JSON，仍可完成评审，摘要在整包接收后显示；不自动重试模型请求。断流、错误和取消不会将半成品保存为完成结果，已有结果与草稿保留。连接测试和提交信息生成仍沿用原有请求方式。

评审只提醒：未评审、评审中、失败、旧版本或有问题都不阻止正常 Git 提交。本次提交评审不发送未暂存编辑；本地理解采用 HEAD 到固定工作区快照（含未跟踪文件），不会改变真实索引或工作文件，也不运行过滤器或钩子。本地理解结果不等于本次提交已评审。暂存内容、HEAD、分支、模型或评审依据改变会使已有结果过期；失败保留旧结果和提交草稿。取消会停止后续处理，服务端已产生的调用仍可能计费。

可视化由模型返回的结构化描述驱动，本地组件负责布局与交互。代码引用先核对固定差异中的路径、版本、行号和摘录；图示只作 AI 行为解释，不能证明真实调用关系或验证通过。旧记录继续展示摘要、文件与风险；重新评审后，模型可补充行为卡片和流程。模型未返回图示或图示无效时明确显示缺失，不补画推测关系。

一次分析最多请求模型两次，合计用量；首次模型未提供有效假设时保留兼容结果，并明确缺少搜索核对。搜索读取相同固定新/旧版本的普通源码，遵循排除、敏感内容和共同预算，合计最多扫描 300 个版本文件、约 150 万字符；显示实际扫描数、截断与未读范围。结论引用必须匹配真实命中，证据不足保持待确认；不执行模型命令、不显示内部推理、不将静态判断当作测试通过。假设、证据片段、图解和结论随结果一起保存，重启后可读。

默认排除常见敏感路径、生成目录、疑似密钥内容、二进制、符号链接和子模块；设置内可调整发送预算与额外排除路径。安全读取最多 1 MB，与发送预算分开：大文件的小差异可以分析，大差异按准确行号分散选取片段并标为部分覆盖。附近上下文合并重叠范围后共享预算，TS/JS、Python 有限识别函数/引用和测试，其余文本含 Markdown 提供附近文本，每版本最多扫描 80 个相关候选。覆盖提示按原因和文件合并、默认折叠，明确区分差异未纳入与附近片段受限。文本匹配不证明真实调用关系，位置核对也不替代对问题真实性的判断。

“改动图解”只展示前后行为与简短结论，核对过程和证据按需展开；“影响流程”单独展示纵向节点图，默认 14px 文字、不自动缩小或截断节点标签。完成进度以紧凑状态行呈现，避免与图解抢占空间。

桌面密钥经系统账户加密保存在 `.local/desktop/model-settings.json`，不会回显。规范、需求与最近评审结果保存在 `.local/desktop/reviews/`，不写入所添加的仓库。环境变量不会自动填入应用设置。模型接口已通过本机模拟 HTTP 服务及真实桌面桥接验证；另已完成下述 DeepSeek 官方 API 合成样例验证。

## 验证

```powershell
npm run test:ux
npm test
npm run build
npm run test:desktop
node scripts/desktop-smoke.mjs --commit-message
```

自动测试创建并清理专用临时仓库，不使用真实开发仓库试写操作，覆盖原有 Git 行为、模型配置与加密、快照范围、相关上下文、排除规则、错误与取消、问题位置、过期状态、评审期间提交和合成样例的已知行为。

提交信息专项使用隐藏窗口验证准备/生成期间切换仓库、准备取消立即恢复、旧响应成功或失败晚到与立即重试，全程使用离线模型，不操作桌面。

真实服务验证入口为 `node scripts/validate-model.mjs --inspect`（默认不联网），配置后显式 `--run` 最多调用四组合成样例，记录实际用量、耗时及待核对的误报/漏报。详见 [真实模型验证流程](docs/model-validation.md)。已用 DeepSeek 官方 API 完成四组合成样例，助手结合独立执行真值核对为两项回归检出、误报 0、漏报 0；不能据此推断真实仓库的总体质量，见[验证证据](.scratch/ai-review/evidence/2026-10-18-deepseek.md)。

桌面集成测试会启动隐藏窗口，验证真实沙箱 preload、IPC、系统密钥加密与本机模型请求，并在带评审问题的专用临时仓库完成提交。若从受限开发沙箱运行 Electron，可能需要在普通用户终端运行；无需关闭应用内的渲染沙箱。

`npm run preview:fixture` 启动一个只连接专用临时仓库的浏览器开发预览，可用于检查完整交互。预览标记为“临时仓库”，使用真实 Git 操作，不连接用户仓库；它不会作为生产桌面服务运行。

`node scripts/preview.mjs --mock-model` 另外连接仅在本机运行的模拟模型，用于验收评审交互。模拟结果有明确说明，不代表真实缺陷。浏览器预览的密钥仅在当前服务进程中保存。
