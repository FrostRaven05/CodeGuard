# CodeGuard

简洁的 Windows 本地 Git 工作台，界面参考 GitKraken。已支持仓库管理、真实差异、整文件暂存与取消、提交预览与提交、彩色分支历史，以及模型配置和本次提交的 AI 评审。

当前 AI 评审针对暂存内容，规范与需求可选填写。全部本地改动、历史提交与分支差异评审、项目规范自动发现、推送、拉取、分支切换和合并仍待后续接入。

## 启动

需要 Node.js 22.12+ 和系统 Git。依赖已经安装时，双击 `Start-CodeGuard.cmd`，或在项目目录执行：

```powershell
npm start
```

首次获取项目后先执行 `npm install`，再启动。Electron 的桌面运行时在首次安装或启动时需要下载。

如果系统 npm 启动脚本配置异常，可直接运行 `node scripts/start.mjs`。开发模式为 `npm run dev`。当前交付为可运行源码，尚未制作独立安装包。

双击启动会隐藏后台控制台；启动日志位于 `.local/launch.log` 和 `.local/launch-error.log`。

## 日常操作

1. 打开已有本地仓库，默认查看全部改动。
2. 点击文件查看该组的真实差异；同一文件可分别出现在未暂存和已暂存组。
3. 文件右侧 `＋` 暂存整文件，`−` 取消暂存。暂存遵循 Git 配置，可能运行仓库配置的 clean filter。
4. 填写提交说明，点击“预览提交”，核对分支与文件后提交。既有钩子和签名设置正常生效。
5. 在“提交历史”选中提交，右侧点击文件查看历史差异。合并提交明确使用第一父视角；历史浏览不切换分支。

从仓库列表移除只解除关联。程序不自动暂存、推送、修改源码或删除锁文件。预览后暂存内容或分支变化需要刷新预览；提交后再次核对实际提交内容。

仓库列表和提交草稿在开发运行时保存在 `.local/desktop/workspace.json`，不会写入所添加的仓库。该目录已排除版本控制。

## 本次提交的 AI 评审

1. 点击右上角“模型设置”，填写兼容 Chat Completions 接口的服务地址（通常含 `/v1`）、模型 ID 与密钥，点击“保存并测试”。也可填写完整 `/chat/completions` 地址。本机免密服务可留空密钥。
2. 暂存要提交的文件，在右栏点击“评审本次提交”。“规范与需求”可选填写，点击评审时保存在本地。
3. 核对发送预览的模型、文件和排除项，点击“发送并评审”。结果显示在右栏，可定位差异行、复制给编码助手；修复由编码助手负责。

评审只提醒：未评审、评审中、失败、旧版本或有问题都不阻止正常 Git 提交。未暂存编辑不会发送。暂存内容、HEAD、分支、模型或评审依据改变会使已有结果过期；失败保留旧结果和提交草稿。取消会停止后续处理，服务端已产生的调用仍可能计费。

默认排除常见敏感路径、生成目录、疑似密钥内容、二进制、符号链接、子模块和超预算内容；设置内可调整预算与额外排除路径。发送前展示实际文件与未覆盖原因。当前仅提供暂存差异和所填依据，不自动读取相关实现或运行检查；结果明确标注“AI 推断待确认”“未核对需求”“检查未运行”。位置核对不能替代对问题真实性的判断。

桌面密钥经系统账户加密保存在 `.local/desktop/model-settings.json`，不会回显。规范、需求与最近评审结果保存在 `.local/desktop/reviews/`，不写入所添加的仓库。模型接口支持已通过本机模拟 HTTP 服务及真实桌面桥接验证；真实服务连通性与模型质量需在填写自己的配置后确认。

## 验证

```powershell
npm test
npm run build
npm run test:desktop
```

27 项集成测试创建并清理专用临时仓库，不使用真实开发仓库试写操作，覆盖原有 Git 行为、模型配置与加密、快照范围、排除规则、错误与取消、问题位置、过期状态和评审期间提交。

桌面集成测试会启动隐藏窗口，验证真实沙箱 preload、IPC、系统密钥加密与本机模型请求，并在带评审问题的专用临时仓库完成提交。若从受限开发沙箱运行 Electron，可能需要在普通用户终端运行；无需关闭应用内的渲染沙箱。

`npm run preview:fixture` 启动一个只连接专用临时仓库的浏览器开发预览，可用于检查完整交互。预览标记为“临时仓库”，使用真实 Git 操作，不连接用户仓库；它不会作为生产桌面服务运行。

`node scripts/preview.mjs --mock-model` 另外连接仅在本机运行的模拟模型，用于验收评审交互。模拟结果有明确说明，不代表真实缺陷。浏览器预览的密钥仅在当前服务进程中保存。
