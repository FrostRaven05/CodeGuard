# CodeGuard

[English](README.en.md)

面向个人开发者的 Windows Git 工作台，用来看懂本地改动、评审即将提交的内容，并由人确认后提交与同步。

CodeGuard 是 Windows 桌面应用。它帮助你阅读一次改动、核对问题和证据，再完成提交、获取、拉取、推送和本地分支合并。历史与差异的布局参考 GitKraken，选择改动的方式参考 VS Code。模型由你自己配置。工具负责解释和评审，编码助手负责修改代码，Git 写操作只在你点击后执行。

评审只提醒，不拦截提交。

## 已经能做

- 打开已有本地仓库，在列表中切换，或只解除关联。解除关联不会删除目录。
- 按未暂存、已暂存、未跟踪查看文件树和真实差异，并整文件暂存、取消暂存或暂存全部。
- 手写提交说明，或根据已暂存差异生成可编辑的 Conventional Commits 草稿，然后提交已暂存内容。
- 浏览彩色分支历史，按说明、作者或哈希搜索，并查看某次提交的差异。
- 获取远端、仅快进拉取、普通推送；切换已有本地分支，核对后合并。冲突留在改动列表中，可在外部解决后继续，或中止合并。
- 有暂存内容时评审本次提交；没有暂存内容时理解全部本地改动。结果包含行为前后对比、影响流程，以及在固定快照中搜索到的证据。
- 打包为 Windows x64 安装版和免安装版。

## 还没做

当前版本没有这些能力：历史提交评审、分支差异评审、项目规范自动发现、手动检查命令、克隆仓库、新建分支、按行暂存、强制推送、硬重置、自动变基、自动 stash，以及内置冲突编辑器。

## 环境

- 系统：Windows
- 从源码运行：Node.js 22.12 或更高，以及已加入 PATH 的 Git
- 安装版和免安装版：不需要 Node.js，仍需要系统 Git

## 启动

依赖已经安装时，双击 `Start-CodeGuard.cmd`，或在项目目录执行：

```powershell
npm start
```

第一次取得项目后先执行 `npm install`。Electron 运行时会在首次安装或启动时下载。开发模式是 `npm run dev`。如果系统 npm 的启动脚本异常，可以直接运行 `node scripts/start.mjs`。

双击启动会隐藏后台控制台。日志写在 `.local/launch.log` 和 `.local/launch-error.log`。

## 打包

在 Windows 上安装开发依赖后执行：

```powershell
npm run package
```

命令会先做类型检查和前端构建，再生成：

- `release/CodeGuard-0.1.2-Setup-x64.exe`：安装版，可选安装目录，并创建桌面和开始菜单快捷方式
- `release/CodeGuard-0.1.2-Portable-x64.exe`：免安装版

文件名中的版本号来自 `package.json`。`npm run package:dir` 只生成 `release/win-unpacked/`，这个目录需要整份保留。第一次打包需要联网下载打包工具和 Electron。

两种打包版都把配置、加密密钥和评审记录放在 `%APPDATA%/CodeGuard/`，不会读入源码运行时的 `.local/desktop/`。卸载默认保留这些数据。当前构建没有代码签名，Windows 可能提示未知发布者。

窗口、任务栏和安装包使用同一套图标。源文件是 `public/codeguard.svg`。修改后运行 `node scripts/generate-icons.mjs`，再重新打包。

## 日常操作

1. 打开一个已有本地仓库。默认显示全部本地改动；这和即将提交的内容不是同一范围。
2. 左侧文件树按未暂存、已暂存、未跟踪分组，目录可以折叠。点击文件，在中间查看该版本的差异。同一个文件可以同时出现在未暂存和已暂存两组。历史提交使用右侧“改动文件”树切换文件。
3. 文件旁的 `＋` 暂存整文件，`−` 取消暂存。标题旁的“暂存全部”按忽略规则处理新增、修改、删除和重命名。没有可暂存内容、索引被锁或仍有冲突时，按钮不可用。暂存遵循仓库的 Git 配置，可能运行 clean filter。
4. 在右侧填写提交说明，或点击“生成提交信息”。生成不弹确认框，只依据已暂存内容，并沿用模型设置中的服务、排除规则和预算。成功结果需要符合 `type(scope): 摘要`；范围可以省略，标题不超过 72 个字符，正文前空一行。不合规的结果不会替换草稿。准备或生成期间如果发生编辑、失败或取消，原草稿会保留。
5. 点击“提交”直接提交已暂存内容。说明为空、没有暂存内容、索引被锁或存在冲突时，按钮不可用。仓库原有的钩子和签名继续生效。失败时草稿保留。程序不会自动暂存、推送、修改源码或删除锁文件。
6. 顶栏“当前检出”显示工作分支。菜单中的分支名称用于浏览历史，也可以切换或合并。历史可以继续加载。搜索默认匹配当前分支中的标题、作者和哈希；“全部历史”恢复所有分支。合并提交的差异使用第一父提交。
7. “获取”更新所选远端的跟踪状态。“拉取”先获取并预览，只做快进。已经分叉时，在同一面板中另行预览一次明确的合并。“推送”先展示本地分支、远端分支和将要发送的提交。没有上游时必须选择远端和分支，也可以勾选建立上游。程序只推送预览中的提交，不做强制推送，也不发送标签。
8. 在目标分支旁选择“切换”或“合并…”。来源、目标、提交和文件在同一面板核对后再执行。切换只针对已有本地分支；远端跟踪分支可以合并进来。
9. 仓库菜单中的“远程仓库管理”可以添加、编辑或删除远端。删除前会说明跟踪分支和上游受到的影响。服务器上的仓库和本地分支都会保留。
10. 合并冲突留在改动列表中。在外部解决并暂存后，从分支菜单或冲突提示中选择“继续合并…”。也可以预览“中止合并…”。Git 无法恢复时，当前现场会保留。

拉取和合并要求工作区干净。切换分支时，由 Git 判断现有改动能否保留，程序不会自动 stash。远端认证使用系统 Git 的凭据或 SSH。认证失败和网络失败分开显示。管理远端地址只修改当前仓库的本地配置，不会为此联网。配置了多个推送地址时，推送会被拒绝，避免一次确认发到多个位置。

## 理解改动与评审

1. 打开右上角“模型设置”，填写兼容 Chat Completions 的地址（通常包含 `/v1`）、模型 ID 和密钥，然后点击“保存并测试”。也可以填写完整的 `/chat/completions` 地址。本机免密服务可以不填密钥。
2. 右侧只有一个分析按钮。有暂存内容时显示“评审本次提交”，只分析索引中的版本。没有暂存内容时显示“理解全部本地改动”，分析工作区和未跟踪文件。点击时会重新读取 Git 状态并固定本次范围。没有改动时按钮不可用。“规范与需求”可以选填，填写后自动保存。
3. 点击后直接进入进度，不弹出发送确认。顺序是：固定版本和附近上下文，由模型提出简短假设，再由程序在这份固定快照中跨目录搜索，最后由模型对照实际命中形成结论。准备阶段取消不会发出请求。请求发出后可以停止等待，但服务端已经产生的调用仍可能计费。
4. 结果先展示行为前后和影响流程，再连接假设、命中片段、结论和修复建议。可以按文件筛选、点击流程节点、缩放流程图，并定位到对应差异行。问题可以复制给编码助手。CodeGuard 不修改代码。

两种范围都请求 Chat Completions 的 SSE 流。过程中只展示已经过敏感内容检查的摘要，以及完成位置核对的问题。供应商的内部推理和原始 JSON 不展示。断流、错误和取消不会把半成品保存为完成结果。

一次分析最多向模型请求两次。搜索只读取这次任务固定下来的普通源码，并遵守排除规则、敏感内容检查和字符预算；两个版本合计最多扫描 300 个文件、约 150 万字符。结论中的引用必须对应真实命中，对不上时保持待确认。程序不执行模型给出的命令，也不把静态判断写成测试已经通过。

安全读取上限是 1 MB，与发送给模型的预算分开。大文件中的小差异可以分析；超出预算的大差异按真实行号分散取样，并标明部分覆盖。附近上下文先合并重叠范围，再分配预算。TS/JS 和 Python 会做有限的函数与引用识别，其他文本只提供附近文字。

从源码运行时，密钥经系统账户加密保存在 `.local/desktop/model-settings.json`，界面不会回显。规范和最近一次评审保存在 `.local/desktop/reviews/`，不会写入所打开的仓库。环境变量不会自动填入设置。打包版使用 `%APPDATA%/CodeGuard/`。

## 验证

```powershell
npm run test:ux
npm test
npm run build
npm run test:desktop
node scripts/desktop-smoke.mjs --commit-message
```

自动测试使用临时仓库，不会在当前开发仓库中试写。`npm run test:desktop` 启动隐藏窗口，检查沙箱桥接、系统密钥加密和本机模型请求。

`node scripts/validate-model.mjs --inspect` 默认不联网。配置真实服务后，显式加上 `--run` 才会调用最多四组合成样例。已完成的 DeepSeek 样例只说明那一组小样本，不能代表真实仓库的总体质量。流程见 [真实模型验证](docs/model-validation.md)。

`npm run preview:fixture` 在浏览器中打开一个只连接临时仓库的开发预览。`node scripts/preview.mjs --mock-model` 再连接本机模拟模型，用来查看评审交互。模拟结果不代表真实缺陷。
