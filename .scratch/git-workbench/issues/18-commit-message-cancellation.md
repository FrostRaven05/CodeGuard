## Diagnosis

`node scripts/desktop-smoke.mjs --commit-message` 使用两个临时仓库、实际 App/React 渲染与沙箱 IPC，将准备请求固定挂起。第一条通过：`App.tsx` 实际使用 `key={commit-message:${activeId}}` 重新挂载组件，旧仓库请求未完成时新仓库可独立生成，旧响应不发送请求或覆盖草稿。因此第一条为误报，模型推测的“不重新挂载”前提在实际入口不成立。

第二条确定失败：取消准备后，`.draft-caption` 仍为“准备暂存内容…取消”，生成按钮仍禁用。命令退出 1；该断言在旧请求保持挂起时检查，排除了“请求恰好完成所以看似取消”的假通过。

核对假设及预测：①取消未释放 phase/activeTask，立即释放后可重试；②旧任务 finally 未核对所有权，新任务准备期间旧响应返回会错误清除进度；③阻塞来自后端生成互斥，若尚未发出模型请求时仍阻塞则不成立。专项验证同时记录实际模型调用次数与仓库草稿。

第一步仅恢复取消按钮时，旧准备返回后的“新任务仍在准备”断言再次失败（false !== true），确认旧 finally 还会清除新任务 phase。最终将成功、失败、收尾及取消失败反馈限制为当前任务所有者，旧任务不再干扰重试。
